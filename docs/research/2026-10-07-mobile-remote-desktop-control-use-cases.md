# 移动端遥控云电脑场景调研与工具层支撑（2026-10-07）

调研对象：用户在手机上把"电脑任务"委托给运行在桌面端/TUI 端（或云电脑）的 AI 代理——即 OpenAI Dots、Meta Muse 所定义的产品形态。本文给出场景/用例（user stories）、对后端平台的能力要求，以及 browser-use / computer-use **工具层**需要为此提供的支撑；末尾映射到 Shannon 本 PR 已落地的改动与仍属后续工作的部分。

竞品框架层的横向对比（工具实现粒度）见同日姊妹篇：`2026-10-07-browser-computer-use-competitor-comparison.md`。

---

## 1. 产品调研

### OpenAI Dots（2026-09-29 DevDay 发布）
- **形态**：ChatGPT 内的"常驻 agent"，每个 Dot 拥有一台专属云电脑（持久存储 + 浏览器 + 完整运行时），并经由 4000+ connectors 接入应用。
- **移动端 UX**：配置需桌面端，之后可从 ChatGPT 手机 App / Slack / Teams / 语音接入；Dot 需要输入时主动发消息，用户可**实时查看 Dot 云电脑的工作画面**。
- **安全护栏**：按动作类型三态规则（允许 / 需审批 / 禁止）；auto-review 分类器决定自动执行/询问用户/用户自己做（改密码永远留给用户）；后台主动研究只读；企业版管理员门控、默认关闭。
- 来源：openai.com/index/introducing-dots；promptessor.com/blog/openai-dots；eweek.com。

### Meta Muse（2026-09 美国区上线）
- **形态**：每用户一台专属 Linux 云 VM（文件系统 + 终端 + 专属 Chromium）。CTO Bosworth："Muse 为每个人配了一台虚拟机，带一个你可以随时接管的专属浏览器。"
- **移动端 UX**：iOS/Android 原生 App + WhatsApp 入口；App 关闭后任务继续；**实时观看浏览器画面、随时接管**；可浏览/下载 agent 工作区文件。
- **安全护栏**（目前公开发布中最深的一套）：敏感动作需用户审批（低风险动作预批放行）；独立 "Sentinel" agent 是网络访问与 connector 的唯一授权方；**审批动作绑定到具体工具输出且在 agent 沙箱之外执行**；**凭据代持（surrogation）**——模型只见占位符，真实密钥在网络边界注入；浏览器子代理**只读无障碍树、不执行 JS**；邮件 connector 剥离 OTP/密码重置链接；购物使用一次性卡号。
- 来源：ai.meta.com/muse/productivity；x.com/boztank/status/2097401864061157821；eigent.ai/blog/meta-muse-personal-ai-agent；deeplearning.ai。

### 其它可比产品（摘要）
| 产品 | 要点 | 移动端 UX | 护栏 |
|---|---|---|---|
| ChatGPT agent（Operator 后继） | 云端虚拟浏览器+终端+文件区 | iOS/Android `/agent`，完成推送通知，跨设备续跑 | 高影响动作确认；watch mode；登录/支付/CAPTCHA 用户接管 |
| Manus | 云 VM + Cloud Browser | 委派后可关 App，**完成推送**；实时观看浏览 | **Take Over 模式**（CAPTCHA/短信/MFA 用户完成后再交还）；隔离加密实例；建议银行类走本地浏览器 |
| Google Mariner → Gemini Computer Use / Agent Mode | 浏览器代理→API computer use | Gemini App Agent Mode | 只控当前标签页；禁 CAPTCHA/密码/支付；购买前确认 |
| Anthropic Claude Computer Use / Chrome 扩展 | 截图驱动桌面/浏览器控制 | **无移动发起流程** | 高危动作确认；域名白名单 |
| Genspark / Proxy / Runner H / Twin | 各类云代理 | 部分有 App | 文档厚薄不一 |

**共性收敛（2026-09 起）**：架构 = "每用户云电脑（VM+浏览器）+ 手机即遥控器"；交互闭环 = **聊天/语音派任务 → （可选）实时观看 → 需审批/需接管时推送 → 完成后交付产物+摘要**。差异化在护栏深度，其中 Muse 的"模型永不见真密钥、只读无障碍树"直指提示注入这一品类共同未解风险。

## 2. User Stories（手机委托电脑任务，20 条）

1. **表单代填**：贴链接+资料 → agent 云浏览器填完 → 推送通知 → 手机看截图 → 推送审批"提交"这一步。
2. **登录态差事**："查下我 Gmail 里客户的回复并起草回信" → 用户在云浏览器登录一次 → agent 在会话内工作 → 完成推送摘要。
3. **MFA 中途接管**：登录遇短信验证码 → 推送"需要你接管" → 用户在流式会话里输码 → 交还 → agent 继续。
4. **CAPTCHA 接管**：同上；agent 明确禁止自行解题。
5. **围观式监督**：在沙发上打开 watch mode，看 agent 订机票的慢轮询截图流+步骤字幕，随时点"接管"。
6. **语音订位**："帮我订周六晚 8 点附近意大利餐厅 4 人桌" → 订完推送确认；要押金则先审批。
7. **受控购物**："找 $400 以下最靠谱的升降桌并买下" → 调研 → 支付前推送商品页+总价审批 → 一次性卡号支付 → 收据推送。
8. **账单谈判/客服代聊**：agent 走运营商取消/客服流程，只把最终承诺动作留给人工审批。
9. **调研报告**："对比这 12 家供应商，出对比表+来源" → 异步云跑 → PDF/表格产物 + 推送，手机看小屏摘要+可展开证据。
10. **数据归集**："把这 30 个房源刮成表格（价格/单价）" → 产物入工作区，手机下载/同步。
11. **文件整理**："从水电 portal 下载所有发票按月归档" → 手机浏览归档后的工作区目录。
12. **常驻监控**："这页价格低于 $150 告诉我"/"每周盯竞品 changelog" → 条件触发才推送+证据。
13. **定时任务**："明早 9 点续费域名并发我收据" → 定时执行；支付步前审批。
14. **长程目标**："两周内帮我规划日本行" → 跨天工作，中途提问（"靠窗还是过道？"）。
15. **政务/文书表单**：多步 portal 表单从工作区文档取数填写 → 标出没把握的字段 → 用户手机纠正 → 审批后提交。
16. **内容工序**："把访谈转写成 show notes + 5 条切片 + 推文串" → 发布到各平台逐一审批。
17. **开发委托**："复现这个 bug、修分支、跑测试、开 PR" → PR 链接推送到手机，手机上评审批准合并。
18. **错误升级**：网站改版卡住/卡被拒 → agent 停下并推送"卡在支付步：卡被拒。换卡重试还是放弃？"——绝不静默失败。
19. **手机端收紧权限**：任务中途用户改规则（"永远别开我的银行域名"）→ agent 立即停相关动作。
20. **跨设备接力**：午间语音派的任务，晚上在桌面端接着看完整操作日志与截屏历史；或反过来。

## 3. 对后端平台的能力要求（网关/引擎层）

任务生命周期：派单 API（消息/语音/URL 模板/定时/触发）→ 任务队列（优先级/并发上限/按用户隔离）→ 每用户云电脑（VM/容器，持久登录态与文件，用户间严格隔离）→ **断连续跑**（关 App 不中断）→ 状态 checkpoint（崩溃恢复不重做已完成步骤）。

进度与可观测：**小屏友好的流式进度**（关键步截图/缩略图时间线 + 步骤自然语言字幕 + 紧凑动作日志）；只读 live view（且不得回流进模型观察，防观察回路）；页面状态结构化摘要（URL/标题/表单字段 digest）；状态变化前后截图留档（审计+错误取证）。

人在回路：**动作级审批门**（停在敏感步骤等待，带超时策略：重问/搁置/放弃）；**同会话接管/交还**（CAPTCHA/MFA 必须在真实会话里完成）；随时插话改指令与硬停止；agent 主动提问并阻塞等待答案。

通信：完成/需审批/需接管/出错四类推送 + 深链，多通道分发（App push / WhatsApp / Slack / SMS / 语音兜底）；最终产物交付（文件/链接/收据/变更清单）+ 小屏摘要。

安全与密钥：按动作类型 allow/approve/block 规则引擎 + 不可覆盖的安全底线；**凭据代持**（模型不见真密钥）；OTP/密码重置链接剥离；一次性/虚拟卡号；域名 allow/blocklist 在**工具层**强制；提示注入防御（内容来源隔离、审批绑定具体动作且由沙箱外组件签发）；全程会话录制与审计；错误分类学（瞬态自动重试 / 阻塞带上下文升级 / 敏感走审批）。

## 4. 对 browser-use / computer-use **工具层**的约束 → 本 PR 落地映射

| # | 约束（调研结论） | 工具层支撑 | 本 PR 落地 |
|---|---|---|---|
| C1 | headed/可流化的渲染面 + **手机可负担的轮询带宽**（"watch it work"） | 轻量截图 | `browser_screenshot` 新增 `format=jpeg` + `quality`（q60 较 PNG 小 ~10×）；`computer` 新增 `zoom` 动作（原生分辨率裁剪小区域，小屏上也能读清验证码/小字） |

| C3 | 同会话接管协议；检测 CAPTCHA/MFA 即升级而非代解 | — | 部分属引擎层后续；工具层 `zoom`+`cursor_position` 服务人工接管后模型重新锚定 |
| C4 | 状态变化前后截图 | 已有 image metadata 管线 | 维持 |
| C5 | **小屏状态摘要**（结构化页面状态） | `browser_snapshot` 元素索引（ref 列表） | 已有；远比 8KB innerText 省流量 |
| C6 | 动作日志可脱敏 | — | 引擎/网关层后续 |
| C7 | 密钥在网络边界注入 | — | 引擎/网关层后续（Muse 式 surrogation） |
| C8 | 只读模式（常驻监控类任务） | computer 已有 `allowed_actions` 白名单 | 已有 |

| C10 | 数据中心 IP 触发 CAPTCHA/风控，人工接管率更高 → **减少无谓轮询** | 减少往返的动作原语 | `browser_wait_for`（等文本出现再截图）；`browser_select_option`（下拉框一步到位）；`browser_hover`（悬停菜单）；组合键 `press_key("Control+Shift+Tab")` |
| C11 | 每任务每用户独立 profile/session | 一次性 temp profile + 显式 opt-in 持久目录 | 已有（session.rs） |

| C13 | 观察卫生（给人看的画面 ≠ 喂模型的观察） | metadata 管线天然分离 | 已有 |

| — | 点击可靠性（hover 引发的布局位移） | 坐标稳定性 | `click_element` 在指针落位后**重测矩形中心**再按压 |

### 尚未落地（明确列为后续）
- 会话内"接管"（人类输入源切换）协议与 live view 通道（网关/桌面层）。
- 凭据代持、域名 allow/blocklist 的工具层强制、动作日志脱敏。
- 截图/录屏的增量流式推送（ws 通道 + 缩略图时间线）。
- 下载文件回传手机（Browser.setDownloadBehavior 落盘后经网关传输）。

## 5. 结论
工具层已具备支撑"手机派单 → 桌面执行 → 小屏围观 → 审批/接管 → 产物回传"闭环所需的**带宽经济性**（JPEG、元素摘要、wait_for）、**操作原语完备性**（下拉/hover/组合键/滚轮/上传/PDF）与**可靠性**（点击重测、wheel 真事件、严格键名防错按）。剩余缺口集中在网关/引擎层（接管协议、密钥代持、流式通道），不阻塞本次工具层改进的价值。
