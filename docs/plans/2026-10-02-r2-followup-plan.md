# R2 后续任务推荐与排期 v2（已批准，R7 裁决记录于 §三.1）

**日期**: 2026-10-02 · **v2**: 经对抗性自查后修订（修订点见 §五变更记录）· **基线**: dev @ daea7303 一带（执行前须重新 fetch）

## 三.1 Rulings R7（用户拍板 2026-10-02）

- **R7-①**：连败不变量 = 「自上次启用以来的调度触发失败」——rerun 与 RunNow 一致排除手动路径；实现采用 run record 增加 trigger 区分（scheduled/run_now/rerun），streak 只认 scheduled。
- **R7-②**：auto-pause 告警不受 notify_on_failure 门控（状态变更≠失败通知，转换时仅一次）；失败告警仍受门控；表单/文案写明边界。
- **R7-③**：F2 采选项 a 阈值混合形态——小文件现状不变（attach 全量解析+徽标）；大文件（尺寸阈值，建议 >10MiB）轻量预检+「将于发送时解析」+发送时全量解析（修大文件双解析债）；不做解析完成事件管线。
- **R7-④**：批次 2 默认排下一迭代，可滑一期不滑一季；滑期前提 F3 已合并；提前触发信号=凭据暴露事故或 OAuth remote 扩量。
- **R7-⑤**：既定管线执行（worktree 分域 briefs → agent 并行 → 双组审查 → 顺序合并）；批次 1 F1-F4 全并行（文件域互不相交），批次 2 另起。

## 三、评审关注点

1. **#1 方向（保留 v1 的对立观点供拍板）**：我把 rerun 从「计入（偏安全）」改为「排除（口径一致）」。保守替代案：维持计入，只做 re-enable 清零。二选一。
2. **F1-③ pause 告警门控**：我建议不受 notify_on_failure 门控（opt-out 用户也必须知道例行被停）。若你认为 opt-out 就是全静默，F1 缩小。
3. **F2 选 a 还是 b**：a 顺带修双解析债但改交互时序（徽标延后到发送回执）；b 保守但保留双解析。我推荐 a。
4. **批次 2 滑期授权**：若 Q4 有更高优先级，F5/F6 可滑，条件是 F3 已合并。
5. **并发会话协调**：执行前 fetch + 重叠域检查（本轮 dev 期间被并发推进 3 个 PR，均为测试基建，与 F 系列文件域不相交——但这是时点事实不是保证）。
