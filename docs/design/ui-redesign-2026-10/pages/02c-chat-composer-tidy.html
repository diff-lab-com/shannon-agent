④

"规划/执行档位"(继承)组件的去向

需求本身成立(Cline 用户的"规划用便宜模型、执行用强模型"工作流),但入口放错了层级。

composer:移除入口(D1)

规划 继承 · 执行 继承 移除

① 措辞 — "继承"是配置优先级链的实现概念(=不覆盖,向上取全局默认),对用户零信息量;
② 作用域反直觉 — 在会话 composer 点选,写入的却是全局 plan_tier/act_tier;
③ 静默失效 — 会话 pin 了模型后该控件无效(其自带提示承认了这点),与模型 chip 的优先级关系无任何视觉表达;
④ 无竞品先例 — Cline 把"Plan/Act 用不同模型"收在设置且 opt-in;Cursor/Claude Code 的 Plan 是权限模式,不做分阶段模型常驻。

Settings → 模型:唯一入口(已存在)

规划阶段继承解析为 claude-sonnet-4-6
执行阶段继承继承全局默认模型

设置页已有同名配置面(settings.models.phaseTier.*)+ 优先级说明与解析预览;composer 的档位需求(尤其"计划模式下用规划档")仍生效,只是不再展示。会话 pin 模型时"档位静默失效"的困惑随入口移除而消失。
