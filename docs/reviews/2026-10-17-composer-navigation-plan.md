## 1. 输入框（composer）交互

### 1.1 现状盘点（结论）

- **"/" 有完整菜单**（15 条静态命令 + list_skills 技能聚合；↑↓/Enter/Tab/Esc 齐全；流式中可用），但：菜单只在「整条输入恰为 `/token`」时出现——打出空格参数即消失、无参数态提示；过滤是前缀/子串（@ 菜单反而是 fuzzy，不一致）；无 /help；技能 `/name args` 是把文本发给模型碰运气。
- **"@" 有文件引用菜单**（工作目录树 600 条 cap + 会话文件索引；4 档打分 fuzzy；键盘导航齐），但**插入即纯文本 `@路径`，无附件语义**——本质是打路径辅助。
- **"+" 附件链路最完整**（菜单+对话框+整窗拖拽+图片粘贴、10 个上限、preflight 预检徽标、chip 可移除），缺口：粘贴只认图片（复制的文件无反应）、无长文本粘贴转附件、chip 无单文件体量（B4 P2-11 有意移除，维持）。

### 1.2 竞品启示（要点）

- 三符号分工（ChatGPT 桌面 / VS Code Copilot）：`@`=上下文、`/`=命令与模式、`$`/`/skill`=技能直呼；skills 同时挂进 @ 菜单降低记忆成本。
- 确定性语义（Windsurf Cascade）：@ 即保证进上下文——与 Shannon 现状（纯文本、模型未必读）是本质差距，但补齐需要后端附件化，非本批。
- Cursor 的多段过滤（选中目录后 `/` 下钻）；ChatGPT 的行中斜杠、非图片粘贴；Cherry/Chatbox 的长文本粘贴转附件；Claude Code 的大文件只传路径降级。

### 1.3 H2 落地范围（本批）

| # | 改进 | 依据 |
|---|---|---|
| 1 | **"/" fuzzy 过滤**：与 @ 菜单同款子序列打分，`/cs` 命中 /cost | 对齐一致性 + Cursor/ChatGPT 的「输入即过滤」 |
| 2 | **"/" 参数态保留**：输入 `/cmd args` 时菜单收起列表、显示一条固定 hint 行（命令描述 + 参数提示 + Enter 直接发送），Esc 退出参数态 | 盘点缺口 2（Claude Code/Cursor 均有参数提示行） |
| 3 | **新增 /help**：聚合展示全部命令+技能（只读卡形态，复用 SlashResultCard 容器） | 盘点缺口 3 |
| 4 | **长文本粘贴转附件**：粘贴文本 ≥8KB 时自动写入临时 .txt 并走附件管线，toast 提示 + Ctrl+Z 可撤销；阈值常量+注释 | Cherry/Chatbox 验证过的主特性；纯前端+现有附件通道，零后端 |
| 5 | 技能/来源封闭、@ 附件化、粘贴任意文件、多段下钻 → **登记不做的项**见 §1.4 | 范围纪律 |

### 1.4 本批刻意不做（登记）

- **@ 附件化 / 确定性注入**：需要后端把 @ 路径升级为结构化附件（或注入保证），涉引擎 wire 变更——单独立项。
- **粘贴非图片文件**：webview 的 clipboard File 无绝对路径，需引入 Tauri clipboard 文件读取能力（插件评估）——单独立项。
- **`$` 技能直呼**：现技能量少，`/` 菜单已含技能；等技能生态起来再评估。
- **slash 行中触发**（不必行首）：价值中等、回归面大（与 @ 检测/IME 交织），登记。
- **队列拖拽排序 / chip 体量显示**：chip 体量是 B4 P2-11 有意移除，不回退。

## 2. 导航

### 2.1 现状（结论）

侧栏一级切换 + 顶栏 14px 上下文标题（G1）；路由查询参数承载会话/项目过滤；无历史前进/后退入口（键盘/鼠标均无）；窗口 title 固定；无返回箭头；重启不恢复上次页面。

### 2.2 竞品证据（要点）

- **历史 back/forward 是真实期待，证据充分**：Cherry Studio #20107（2026-09）「tab 化浏览器形应用里按 Alt+← 是条件反射，而我们现在毫无反应」，一个月内 PR #20769 落地（⌘[/⌘] mac、Alt+←/→ win/linux、鼠标侧键、栈不可动时 no-op）；Slack 官方一级快捷键；Notion 桌面版专门补了 ⌘[/⌘]；Discord 鼠标侧键默认开启。
- **形态**：轻量（快捷键 + 至多一个返回箭头），不是浏览器 chrome；设置等嵌套页用返回箭头（Claude）而非面包屑。
- **窗口 title 随路由变化**：Notion/Obsidian 做对了；Slack/Discord 固定 title 是被反复吐槽的缺陷。
- **重启恢复上次位置**：Slack/Discord/Obsidian 的隐式契约。

### 2.3 H3 落地范围（本批）

| # | 改进 | 依据 |
|---|---|---|
| 1 | **历史后退/前进快捷键**：Alt+←/→（Win/Linux）+ ⌘[/⌘]（macOS，经 mod 键映射），走 React Router 历史栈，栈不可移动时 no-op | Cherry PR #20769 同款形态 |
| 2 | **顶栏返回箭头**：仅当历史可后退时显示（canGoBack），点击 navigate(-1)；带 aria-label | Claude 设置内返回箭头模式 |
| 3 | **窗口 title 联动路由**：`document.title = 页面上下文 · Shannon`（复用 header.title.* 键；会话页带会话名） | Notion/Obsidian 惯例；Slack 反面教材 |
| 4 | **重启恢复上次位置**：localStorage 记录最后路由（排除 /welcome /timeline/:id 等瞬态），启动时无存储会话意图则恢复 | Slack/Discord 隐式契约 |
| 5 | 鼠标侧键、面包屑、tab 化外壳 → **登记不做** | 见 §2.4 |

### 2.4 本批刻意不做（登记）

- **鼠标侧键**：Tauri webview 对 button3/4 的派发因平台而异，无法稳定测试——快捷键先行，侧键依赖 webview 原生行为（若平台原生支持则自然可用）。
- **面包屑**：Shannon 的层级（设置节、任务详情）用「页内标题+返回箭头」已覆盖；真树状层级（项目→会话）出现时再评估（Notion 模式）。
- **tab 化外壳**（Cherry v2 模式）：重度多任务向，与单窗口工作台定位冲突，登记。
- **macOS 双指滑动**：Cherry/Electron 十年未解，不碰。
