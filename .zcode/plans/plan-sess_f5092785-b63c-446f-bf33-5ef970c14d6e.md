## P1d 后续改进计划（feat/agent-eval-bench 分支，等你审核）

### 0. 背景与目标

P1d Terminal-Bench 2.1 全量 89 题：**shannon+glm-5.3-flash 36/89 = 40.4%**，GLM 官方同模型 Claude Code harness 69.2/89 = 77.8%，**差额 33 题**。

差额分解（两份独立调研一致）：

| 损失类别 | 题数 | 占缺口 % | 成本 | 预期回收 |
|---|---:|---:|---|---|
| 上游 API 6-min 超时（Request timed out） | **21** | **63.6%** | 低 | +15–18 |
| 部署：GLIBC 不兼容（qemu-*） | **2** | **6.1%** | 中 | +2 |
| 适配器 CLI 启动 bug（`-` 开头 prompt） | **1** | **3.0%** | 极低 | +1 |
| Verifier 缺 uv/python-build-standalone | 9 | — | 跨 harness | 后续 |
| 真能力差距（模型 + 工具语义） | ~10 | — | 高 | 本轮不动 |

**目标**：把 40.4% 提升到 ~52–58%（+10–15 题），聚焦低成本高 ROI 的脚手架改动。

### 1. 实施阶段

**阶段 A — 适配器即时修复**（半天，+6–10 题）
1. Harbor 适配器注入 `SHANNON_STREAM_IDLE_SECS=180`（A1 看门狗默认开），让 21 个流超时题自动 retry
2. 适配器 CLI 启动：`shannon -p -- '<prompt>'` 或 heredoc 形式，救 pytorch-model-recovery
3. 移除 harbor `--disallowed-tools WebFetch/WebSearch`（部分题需要文档）

**阶段 B — engine/工具改造**（1–2 天，+4–6 题）
4. Request-level retry：`ApiError::Timeout` 自动重试一次（`crates/shannon-engine/src/api/error.rs`）
5. 新增 `RunBackground`/`WaitForLog`/`KillPid` 工具（`crates/shannon-tools/src/system.rs`），针对长时后台 task
7. `SHANNON_TOKEN_BUDGET` 看门狗：context 超阈值强制合成压缩消息（针对 token 雪崩题）
8. `no_progress_strikes` headless 模式自动启用（`crates/shannon-core/src/auto_test.rs:111`）

**阶段 C — 部署/打包**（半天，+2 题）
9. 增加 `x86_64-unknown-linux-musl` target，构建静态二进制覆盖 qemu-* 等 alpine 镜像

**阶段 D — 验证与回归**（1 天）
10. 抽样复测 30 题分层子集（21 流超时 + 2 GLIBC + 1 CLI bug + 6 control PASS）
11. 更新发现文档与最终汇总
