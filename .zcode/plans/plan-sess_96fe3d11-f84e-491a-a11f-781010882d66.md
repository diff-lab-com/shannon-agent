## 改动 1(问题 1,核心修复):§G-rev3 — re-paired 只重建 recv、保留 send counter

文件:`gateway/src/mobile/relay/relayHost.ts`

- `case "paired"`(L160-181):`recvChannel = new E2eChannel(...)`(L165)保持无条件重建(§G-rev2 纵深防御,容忍丢失 counter 状态的手机);`sendChannel = new E2eChannel(...)`(L164)改为**仅在 `sendChannel === null` 时创建**,否则保留既有实例维持单调 counter。
- 同步修正两处注释:L163("counters restart"已不成立)、L185-187 `peer_gone` 分支里"The send channel is also reset and will be recreated"的过时描述。
- `peer_gone`(L183-191)逻辑本身不动(已经不清 sendChannel)。
- 正确性依据:同一 host 进程内 sessionKey 恒定(bootstrap.ts:205 启动时一次性派生);host 进程重启走既有 `host_replaced` 语义,phone 会复位 recv,不受本改动影响;新 phone 实例 recv 从 0 起步,接受任意 ≥1 的 counter,不会楔死。附带收益:host 方向的 (key, nonce) 重用窗口(§G-rev1)一并封闭。

## 改动 2(问题 1 测试):钉死 host send counter 连续性

文件:`gateway/src/mobile/relay/__tests__/relayHost.test.ts`

- 新增用例 "preserves host send counter across re-paired (§G-rev3)":第一会话 phone 发帧→用原始 WS message 捕获 host 响应帧,断言 wire counter = 1n 并用 `phoneRecv1.open()` 解码;phone 断开(peer_gone)→重连;**跨重连复用同一个 `phoneRecv1` 实例**(镜像手机侧 `relay_transport.dart`:phone 角色 re-paired 不复位 recv)→再次捕获 host 响应原始帧,断言 wire counter = 2n 且解码成功。该断言在现状代码下必红(counter 回到 1 触发 replay 拒收),修复后转绿。
- 现有 re-pair 用例(L326-390,recv 复位契约)保持通过。

## 改动 4(问题 3):桌面侧 mDNS 广播 + QR host 改 .local + 默认绑 0.0.0.0

- `gateway/package.json`:新增依赖 `bonjour-service`(纯 JS,mDNS/Bonjour 发布)。
