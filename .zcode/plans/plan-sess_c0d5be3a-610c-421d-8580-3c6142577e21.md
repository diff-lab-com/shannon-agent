# 计划：编译 shannon CLI → 冒烟测试 → 用 glm-5.3-flash 生成 3 个游戏 → 运行评估并出改进方案

## 产物位置（持久化）
`/home/ed/workspace/app/work/shannon/shannon-code-games/`（仓库兄弟目录，不污染 git）
- `game-2048/`、`game-mario/`、`game-racing/` — 三个自包含网页游戏
- `logs/` — 每次 shannon 运行的完整 stdout/stderr 日志
- `eval-artifacts/` — 评估截图 + `EVALUATION.md`（问题清单 + 改进方案）

## Phase 0：预检
1. 读 `scripts/eval/wrapper-glm.sh`，照抄其环境卫生模式（`env -u ANTHROPIC_API_KEY -u OPENAI_API_KEY …`，key 用已有的 `SHANNON_API_KEY`/`~/.shannon/credentials/zhipu.json`，不打印明文）。
2. 确认 `SHANNON_API_KEY` / `ZHIPU_API_KEY` 存在（只查存在性）。

## Phase 1：编译 CLI（当前 dev @ 63e2b11c）
- `just build-code`（= `cargo build --release -p shannon-cli`），后台运行并轮询（release 开 LTO、jobs=4，可能较久）。
- 失败/超时则回退 `cargo build -p shannon-cli`（debug，target/debug/shannon 昨天刚编过，增量很快）。
- 验证产物：`shannon --version`（应输出 0.11.0）、`--help`、`doctor`、`list-providers`。

## Phase 2：测试 CLI
1. 冒烟：`--version` / `--help` / `doctor`。
2. 真实连通性测试（后台跑，避免占前台）：
   `cargo nextest run -p shannon-cli`（443 个测试，结果写入日志，只汇报结论）。
3. Live 小请求：`shannon --provider zhipu-coding-plan --model glm-5.3-flash -p "用一句话回答：1+1=?" --yes --max-turns 2`，确认模型链路通。

## Phase 3：生成三个游戏（顺序执行，每个独立文件夹）
每个游戏在其文件夹内运行（shannon 以当前目录为工作区）：
```bash
cd <game-folder> && env -u ANTHROPIC_API_KEY -u OPENAI_API_KEY -u SHANNON_MODEL -u SHANNON_PROVIDER -u SHANNON_BASE_URL \
  <built-shannon> --provider zhipu-coding-plan --model glm-5.3-flash \
  --goal "<完成标准>" -p "<详细需求>" --yes --max-turns 60 \
  --allowed-tools Read,Write,Edit,Bash,Glob,Grep --disallowed-tools WebFetch,WebSearch \
  --output-format json-stream > ../logs/<game>.ndjson 2>&1
```
- 后台运行 + 轮询；`--goal` 在 headless 下做目标注入，配 `--max-turns` 保证单次长时间运行。
- 每个游戏的 prompt 要求：纯 vanilla JS + Canvas、单文件夹自包含、零外部依赖（不用 CDN、离线可玩）、双击/静态服务即可运行、附 README.md（含运行方式与操作说明）。
  - **2048**：4×4 网格、方向键+触控滑动、合并动画、计分与最高分(localStorage)、胜利/失败判定、新游戏按钮。
  - **超级马里奥**：横版平台跳跃，跑/跳/敌人(蘑菇怪)/金币/障碍管道/旗杆过关、至少 2 关或够长的单关、死亡与重生、相机跟随。
  - **赛车**：方向盘转向+油门刹车（方向键）、赛道或公路避障、速度表/圈速或里程计分、碰撞判定与重开。
- 完成校验：`index.html` 等文件存在 + `node --check`（对 js 文件）语法过。若未完成（退出码 2=turns 耗尽或缺文件），用 `-c` 续跑至多 2 轮（"继续完成…"）——以此模拟 goal 的持久推进。
- 退出码 4（限流）则等待后重试。

## Phase 4：运行并评估三个游戏
用本地 http 服务 + 浏览器（agent-browser / control-browser skill）逐个实测：
1. `python3 -m http.server <port>` 起服务，浏览器打开、截图、收集 console 错误。
2. 交互实测：键盘事件驱动（2048 方向键合并/计分是否正确、马里奥跳跃碰撞、赛车转向与碰撞），每游戏多张截图留证到 `eval-artifacts/`。
3. 代码走查：结构、明显 bug、死代码、难度曲线、移动端适配等。
4. 写 `eval-artifacts/EVALUATION.md`：每个游戏的问题清单（按 P0-P3 分级 + 截图证据）+ 对应改进/实施方案（含 shannon CLI 生成质量本身的观察，如 prompt 遵循度、工具使用行为）。

## Phase 5：汇报
最终消息给出：编译/测试结论、三个游戏生成结果与路径、实测发现的问题汇总、改进方案要点、EVALUATION.md 及各产物路径。
